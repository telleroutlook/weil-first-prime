# FP-0.35 Certificate Bug Report (2026-08-07)

## Severity: CRITICAL — the FP-0.35 "PROVED" certificate does not hold under correct code.

## Summary
The certificate `pilots/cert_schur_correct_cL.json` (generated by
`scripts/reproduce_fp035.py`, commit afbc0eb) claims the even sector at
L=7/20, N=8 gives min_eig=+0.01494, certified=True. This is WRONG due to two
compounding bugs, both biasing the criterion toward a false PASS.

## Bug 1 — incomplete S^(0) (missing three of four terms)
The residual R_0 = S^(0) - M0^T G^{-1} M0 requires (per main.tex):
    S^(0) = || (V+K) p ||^2 = S_VV + S_VK + S_KV + S_KK   (FOUR terms)
- `reproduce_fp035.py:135` sets  S0 = integrate_S_KK   (ONLY S_KK)
- `o1b_gate.py:282` correctly sets S0 = S_VV + S_VK + S_KV + S_KK
Missing the positive S_VV+S_VK+S_KV shrinks R_0, loosening the criterion.

## Bug 2 — wrong positivity judge
- Certificate uses min-EIGENVALUE of symmetrized C_float (+0.0149 claimed).
- Correct judge is min-PIVOT of LDL^T (o1b_gate `_min_pivot_mpmath`).
For an indefinite symmetric C, min-pivot<0 while symmetrized min-eig can be
marginally positive. min-pivot is the correct positive-definiteness test.

- Even min_pivot is NEGATIVE for all eta (best -0.019 at eta=5). FAIL.
- Even min_eig with correct S0 is only +0.0009, NOT the certificate's +0.0149
  (16x smaller) — confirming +0.0149 came from the S_KK-only bug.

## Consequence
- FP-0.35 N=8 does NOT satisfy the (sufficient) Schur criterion under correct
  code. The "PROVED" status is INVALID as of this bug.
- This does NOT prove lambda(7/20) <= 0. Schur is sufficient only; RH true =>
  lambda(7/20) > 0 almost certainly. The N=8 certificate is simply too weak.
- `scripts/scan_lambda_profile.py` shares Bug 1 (S0 = S_KK only), so ALL
  L=0.42 verdicts from it are also invalid and must be recomputed.

2. Fix reproduce_fp035.py and scan_lambda_profile.py to use four-term S0.
